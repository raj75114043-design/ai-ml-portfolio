**Engineering standards across these projects:**

- Every repository ships a Streamlit or FastAPI application, a pytest suite and GitHub Actions CI
- Docker images are published automatically to GitHub Container Registry on every push
- Retrieval and generation evaluated separately — Recall@K, MRR and citation coverage
- Agent workflows with explicit termination conditions, iteration caps and tool-call tracking
- Server-side tool validation and least-privilege access for every MCP tool
- Imbalanced-data and time-series best practice — PR-AUC, cost-based thresholds, chronological splits, leakage tests
- All data is synthetic; no client names, data or proprietary code

## Production RAG — Technical Profile

| Component | Implementation |
|---|---|
| **Vector Store** | Pinecone (1536-dimension embeddings), FAISS (IVF) |
| **Scale & Latency** | 100K+ documents served at under 200 ms |
| **Retrieval** | Hybrid — 80% dense semantic + 20% BM25 sparse, fused and reranked |
| **Chunking** | Semantic chunking — 512 tokens with 100-token overlap |
| **Conversation** | Standalone query rewriting for multi-turn context |
| **Quality** | Hallucination mitigation with RAGAS evaluation targets above 0.8 |
